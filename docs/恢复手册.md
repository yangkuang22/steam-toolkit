# 恢复手册（Steam 更新 / 出问题时的处理）

## 第一原则：**你的系统不会坏**

```
✓ /usr/bin/steam 从未被修改（仍然是系统原版）
✓ 注入只影响 Steam 一个程序，不碰系统
✓ 启动器有 4 道回退检查，任何异常都自动用"普通模式"启动 Steam
✓ 所有原始文件都备份在 ~/steam-toolkit/backup/
```

**最坏情况**：Steam 正常打开，只是"库里看不到解锁的游戏"。

---

## 出问题时的处理顺序

### 第 0 步：先跑健康检查（10 秒）

```bash
bash ~/steam-toolkit/scripts/healthcheck.sh
```

它会告诉你哪一项有问题。

### 第 1 步：如果 Steam 打不开（几乎不会发生）

**立刻用无注入模式启动**：

```bash
~/.local/bin/steam-noinject
```

**或者更暴力（直接调用系统二进制（不经包装器））**：

```bash
/usr/bin/steam-jupiter
```

**这两个都不依赖任何我装的东西，一定能开。**

### 第 2 步：如果 Steam 能开，但游戏不见了

**这是 Steam 更新导致特征码失配**（最常见的情况）。确认：

```bash
grep -E "pattern summary|Failed to find all" ~/.SLSsteam.log | tail -2
```

- `missing=0` → 特征码正常，问题在别处
- `missing=N`（N>0）→ **特征码失配**，见下面"修复特征码"

### 第 3 步：修复特征码（Steam 更新后）

**方法 A：重新编译（推荐，一劳永逸）**

```bash
. ~/SteamUnlockOS/buildenv.sh      # 新安装是 ~/steam-toolkit/buildenv.sh
cd ~/slsplus-build
make -j8 bin/SLSsteam.so bin/library-inject.so
ldd bin/SLSsteam.so | grep "not found"   # 必须没有输出，否则启动器会拒绝注入
cp bin/SLSsteam.so bin/library-inject.so ~/.local/share/SLSsteam/
```

> 光重编不改特征码是没用的——特征码写在 `~/slsplus-build/res/patterns.toml` 里，
> 编译时才会打包进 .so。Steam 变了就得先改这个文件。

**先看原版 SLSsteam 有没有适配（最省事）**：SLSsteam-Plus 是 AceSLS/SLSsteam 的分支，
Plus 的作者更新慢，原版通常 1~2 天内就适配新 Steam。去看
`github.com/AceSLS/SLSsteam` 最近带 `chore(patterns)` / `chore(sdk)` 的提交：
- `chore(patterns)` → 特征码，可以翻译成 patterns.toml 的写法
  （原版 `std::vector<int16_t>{0x56,0x57,0xE5,0x89,0x55}` = Plus 的 `prologue = "56 57 E5 89 55"`）
- `chore(sdk)` → **Steam 内部数据结构变了**，Plus 里同名的 `src/sdk/*.hpp` 也要照改，
  否则特征码全找到了也会**启动 30 秒左右崩溃**（症状：启动器日志写"30 秒内正常退出"，
  `coredumpctl list` 里有 SIGSEGV，栈里是 SLSsteam.so）
- `chore(SafeMode)` 里有新版 steamclient.so 的 sha256，和本机
  `sha256sum ~/.local/share/Steam/ubuntu12_32/steamclient.so` 一致，就说明是同一版 Steam，可以放心照抄

> 改完的源码要同步回仓库：`cd ~/slsplus-build && git diff > <仓库>/scripts/slsplus.patch`。

**2026-10-15 那次（Steam 1791918634）实际改了什么**，供下次参考：
| 问题 | 处理 |
|---|---|
| 9 个特征码失配（5 个必需） | 3 个照抄原版；GetAppByID/MarkAppChange 只是一个偏移变了（改成通配）；IClientUserStats 只是开头的哈希变了；SharedConfigWriteCallsite 通配栈偏移 |
| CAPIJob::GetPlayerStats 找不到，原版也已经删了这个钩子 | 改成可选，hooks.cpp 里找不到就跳过（只影响默认关闭的 OfflineAchievementsSchema） |
| CNetPacket / CProtoBufMsgBase 结构整体后移 8 字节 | 照原版 sdk 提交改 `src/sdk/` 两个头文件（不改就 30 秒崩溃） |
| 新编译的 .so 要求 GLIBC_2.43（系统只有 2.41） | buildenv.sh 已修：libm 改为链接系统自带的那份 |

**方法 B：试试在线特征码**

```bash
# 编辑配置，把 OnlinePatterns 改成 true
sed -i 's/^OnlinePatterns = false/OnlinePatterns = true/' ~/.config/SLSsteam/config.toml
```

**方法 C：拉上游最新源码重编**

```bash
cd ~/slsplus-build
git pull
# 注意：git pull 会覆盖我们的修补，需要重新打补丁（见 构建说明.md）
```

### 第 4 步：完全回滚到"未修改"状态

```bash
# 1. 用系统默认方式启动 Steam（不带任何注入）
/usr/bin/steam-jupiter

# 2. 如果想彻底移除注入（可选）
mv ~/.local/share/SLSsteam ~/.local/share/SLSsteam.disabled
rm ~/.local/share/applications/steam.desktop   # 恢复系统默认桌面图标
update-desktop-database ~/.local/share/applications
```

**这样做之后，你的 Steam 就和从没装过 SLSsteam 一模一样。**

## 各种"坏情况"对照表

| 症状 | 原因 | 处理 |
|---|---|---|
| **Steam 打不开** | 极少见（启动器已加固） | `~/.local/bin/steam-noinject` |
| **库里游戏不见了** | 特征码失配 | 重新编译（第 3 步） |
| **游戏显示"购买"而不是"安装"** | 访问权限模拟失效 | 检查 `config.toml` 里 `PlayNotOwnedGames = true`，以及 `~/.config/SLSsteam/lua/<appid>.lua` 是否存在（所有权只走 Lua，`AppIds` / `AdditionalApps` 应保持为空） |
| **点安装后"内容加密"** | 缺 depot 密钥 | 重新跑 `install-mh3 <appid>` + **重启 Steam** |
| **游戏下到 0 字节空壳** | 缺清单 | 检查 `depotcache/` 里有没有 `<depot>_<gid>.manifest` |
| **注入日志说 abort** | 特征码失配 | 第 3 步 |
| **Steam 更新后一切正常** | 特征码没变 | 什么都不用做 |

## 关键路径速查

| 用途 | 路径 |
|---|---|
| **无注入启动（安全网）** | `~/.local/bin/steam-noinject` |
| **系统原版 Steam** | `/usr/bin/steam-jupiter` |
| 带注入启动 | `~/.local/share/SLSsteam/path/steam` |
| 启动器日志 | `<项目目录>/logs/launcher.log`（每次启动的完整日志在 `logs/blackbox/`） |
| SLSsteam 日志 | `~/.SLSsteam.log` |
| 备份目录 | `~/steam-toolkit/backup/` |
| 健康检查 | `bash ~/steam-toolkit/scripts/healthcheck.sh` |
| 构建环境 | `. <项目目录>/buildenv.sh`（真机上是 `~/SteamUnlockOS`） |
| SLSsteam 源码 | `~/slsplus-build/` |

## 备份清单（都在 ~/steam-toolkit/backup/）

| 备份 | 内容 |
|---|---|
| `slssteam-orig/share-full/` | 原始 SLSsteam 库（上游版） |
| `slssteam-orig/config/` | 原始配置（config.yaml） |
| `slssteam-orig/steam-wrapper.bak` | 原始启动器 |
| `config.vdf.autobak` | 我改密钥前的 config.vdf |
| `config.vdf.before-cleanup` | 清理无效密钥前 |
| `desktop/` | 原始桌面文件 |

**恢复单个文件**：
```bash
cp ~/steam-toolkit/backup/slssteam-orig/share-full/SLSsteam.so ~/.local/share/SLSsteam/
```

## 什么时候"重新编译"能解决问题

| 情况 | 重编有用吗 |
|---|---|
| Steam 更新，特征码变了 | ✅ **有用**（如果上游已适配） |
| Steam 改了内部结构（大版本） | ⚠️ 可能要等上游 |
| 配置写错了 | ❌ 不用重编，改配置就行 |
| 密钥错了 | ❌ 不用重编，重跑 install-mh3 |
| 注入库损坏 | ✅ 重编或从备份恢复 |
